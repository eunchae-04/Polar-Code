# `scl/` — SCL(Successive Cancellation List) 디코더

`scd/`의 SC 디코더가 가진 "한 번 잘못 판단하면 되돌릴 수 없다"는 구조적 한계를 보완하기
위해, 여러 후보 경로를 동시에 유지하는 **SCL(List) 디코더**로 확장한 버전입니다. 난수
생성, AWGN 채널, Frozen Mask 계산, Polar 인코더는 `scd/`와 동일하고, **디코딩 부분만**
리스트 기반으로 바뀌었습니다.

---

## 파일 구성

| `polar_code_SCL_sim.c`              | 이 폴더의 메인 소스        |
| `result/simulation_results_scl.txt` | 실행 시 자동 생성되는 결과 |

## 환경 설정

```bash
gcc -O2 -Wall -o polar_code_SCL_sim polar_code_SCL_sim.c -lm
```

이미지/Python 의존성 없음. `scd/`와 마찬가지로 무해한 `-Wmaybe-uninitialized` 경고가
뜰 수 있습니다.

---

## 실행 방법

```bash
./polar_code_SCL_sim
```

`scd/`와 동일한 SNR 범위(0.0~3.0dB, 0.25dB 간격)를 스윕합니다.

### List Size 조절

```c
#define LIST_SIZE 8
```

이 값을 2, 4, 16, 32 등으로 바꿔서 재컴파일하면 "리스트 크기 대비 성능/계산량" 트레이드
오프를 직접 실험해볼 수 있습니다. `L`이 클수록 성능은 좋아지지만 계산량도 대략 L배로
늘어납니다. `L=1`이면 사실상 SC 디코더와 동일하게 동작합니다.

## 핵심 이론 (요약)

|                | SC                   | SCL                                          |
| -------------- | -------------------- | -------------------------------------------- |
| 탐색 경로 수   | 항상 1개             | 최대 L개 동시 유지                           |
| 비트 결정 방식 | LLR 부호로 즉시 확정 | 0/1 둘 다 후보로 남기고 Path Metric으로 평가 |
| 되돌리기       | 불가능 (오류 전파)   | 나중에 더 나은 경로가 살아남을 수 있음       |
| 계산량         | 기준                 | 약 L배                                       |

**Path Metric**: 각 경로가 "얼마나 그럴듯한가"를 나타내는 누적 점수. 결정한 비트가 LLR
부호와 일치하면 그대로, 불일치하면 `|LLR|`만큼 페널티를 더합니다.

**Pruning(가지치기)**: 정보비트마다 후보가 최대 2배로 늘어나므로, 매번 Path Metric이
좋은 상위 `LIST_SIZE`개만 남기고 나머지는 버립니다. 이게 없으면 후보 수가 기하급수적으로
폭발합니다.

**origin 배열**: 리스트가 쪼개지고 합쳐지는 과정에서 "지금 이 슬롯의 경로가 원래 어느
슬롯에서 갈라졌는지"를 추적하는 이름표. 이 프로젝트의 SCL 구현에서 가장 까다로운 부분이며,
자세한 예시는 아래 문서에 정리되어 있습니다.

**최종 선택**: CRC 없이, 살아남은 후보 중 Path Metric이 가장 작은 경로를 최종 디코딩
결과로 채택합니다.

> **더 자세한 설명**: 프로젝트 최상위의 `polar_SCL_code_explained.md`에 `origin` 배열
> 동작 예시를 포함해 코드 전체를 상세히 설명해두었습니다.

## 출력 결과물

`result/simulation_results_scl.txt`(SNR-BER-FER)와 Gnuplot 그래프가 생성됩니다.
`scd/`의 결과와 비교하면 리스트 디코딩의 성능 이득을 확인할 수 있습니다 (별도의 비교
도구를 만든다면 두 결과 파일을 함께 참조하면 됩니다).

## CRC-aided SCL로의 확장 (향후 계획)

현재는 CRC 없이 Path Metric만으로 최종 경로를 선택하는 가장 단순한 형태의 SCL입니다.
실제 5G NR 표준 등에서는 CRC를 붙여 "CRC를 통과하는 후보 중 Path Metric이 가장 좋은 것"을
고르는 CA-SCL(CRC-Aided SCL) 방식을 많이 사용하며, 이는 다음 확장 방향으로 검토 중입니다.
